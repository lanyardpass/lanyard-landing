export const weekData = (() => {
  const start = new Date(eventsSnap.snapshot_date + 'T00:00:00Z');
  const buckets = Array.from({ length: 13 }, (_, i) => {
    const d = new Date(start.getTime() + i * 7 * 86400000);
    return {
      label: d.toLocaleDateString('en-US', { month: 'short', day: 'numeric', timeZone: 'UTC' }),
      value: 0,
    };
  });
  for (const ev of eventsSnap.events) {
    for (const ds of ev.dates ?? []) {
      const idx = Math.floor((new Date(ds + 'T00:00:00Z').getTime() - start.getTime()) / (7 * 86400000));
      if (idx >= 0 && idx < buckets.length) buckets[idx].value += 1;
    }
  }
  return buckets;
})();

export const stats = (() => {
  const nights = eventsSnap.events.reduce((n, e) => n + (e.dates?.length ?? 0), 0);
  const parks = new Set(blockoutsSnap.operators.flatMap((o) => o.parkNames)).size;
  const tiers = blockoutsSnap.operators.reduce((n, o) => n + o.tiers.length, 0);
  return [
    { value: String(eventsSnap.events.length), label: 'events curated in the next 90 days' },
    { value: String(nights), label: 'dated event nights on the calendar' },
    { value: String(tiers), label: 'pass tiers with blockout coverage' },
    { value: String(parks), label: 'parks tracked' },
  ];
})();

This post never ships. It's the internal reference for what the Lanyard blog can physically do, every block in one scrollable place, so that when a real post is being planned we can point at this page and say grab that one, and that one, and we'll need to go shoot that.

Three things to know while you scroll. First, every demo uses real Lanyard content where we have it (real photos, the real events corpus, a real app screenshot), and an honest labeled placeholder where we don't. Second, this post has no hero image *on purpose*. The frontmatter supports `hero`/`heroAlt`/`ogImage`, and the weather post demonstrates that path; this one demonstrates the fallback (the blog index card shows the brand panel instead). A real post should almost always ship a hero, since it's also the social share card. Third, the amber chips are the shopping list.<SideNote n={1}>The chips are a component too (`CaptureSpec`). Real posts never include them, they exist so this page doubles as a capture checklist.</SideNote> Wherever you see one, that block is waiting on media we haven't captured yet, and the chip says exactly what to go get.

## Words first

Plain prose is the default, and it already handles **bold**, *italics*, [links to other posts](/blog/weather-system-nobody-asked-for), `inline code`, and lists without any components. That covers maybe eighty percent of a post. The rest of this section is what we reach for when a paragraph isn't enough.

A **pull quote** takes our best sentence and sets it large enough to screenshot. Use one per post, maybe. It's the line we'd want quoted back at us.

<PullQuote>
The sky on your card is drawn from the real forecast, down to tonight's actual moon.
</PullQuote>

A standard **blockquote** is for someone else's words. It stays quiet and italic, because the voice isn't ours.

> A beta tester watched a raindrop run down the glass, trailing a short wet track behind it, and described it with one word, "biological."

**Callouts** carry the aside that matters. Three variants, all in the green family. `info` is the default, `tip` is louder, `note` is quieter.

<Callout variant="tip" title="The passholder move" icon="🎢">
This is the callout style. Use it for the thing a passholder should actually *do* with the information, not for decoration. If every section has one, none of them work.
</Callout>

A **LocalAside** is the dark block for lived-in Orlando knowledge. It's deliberately the visual opposite of the page, because it's the moment the founder leans over and talks off the record.

<LocalAside title="From a local: what this block is for" bg={ceiling} bgAlt="A gold constellation ceiling.">
The insider tip goes here. Parking tricks, which entrance, what time the line actually dies. This block earns its contrast by being rare and by being right. The background photo is optional.
</LocalAside>

A **NerdBox** hides the deep end behind a click, so the math-curious get their reward and nobody else pays for it. Code inside gets Shiki syntax highlighting at build time, no client JavaScript.

<NerdBox title="How payback actually accrues">
The simplified shape of the app's payback math, which is the kind of thing that belongs in one of these.

```swift
// Simplified. The real rulebook has more edges (same-park-twice days,
// park-to-park increments, perk frequency caps).
var totalRecovered: Decimal {
    let visitValue = visits.reduce(0) { $0 + $1.gatePriceThatDay }
    let perkSavings = perkUsages.reduce(0) { $0 + $1.valueSaved }
    return visitValue + perkSavings
}
```

Every visit is valued at what a one-day ticket to that park cost *on that date*, not at an average. That single decision is most of the rigor.
</NerdBox>

Small **markdown tables** work inline for quick facts. (Real comparisons should use the TierTable component instead, which collapses to cards on phones.)

| Block | Job | Frequency |

| Pull quote | The screenshotable line | One per post |
| Callout | The actionable aside | A few |

## The shopping list

Everything above, reduced to what goes in the camera roll. This is the standing list for any park day where content is a goal.

- **Stills, always.** 3–6 per post minimum, shot wider than feels right, and one strong enough to be the hero/share card.
- **The matched pair.** One framing, two moments. Feeds the CompareSlider and the ChronosDissolve both.
- **The day series.** One framing, 4–6 beats of one day, tripod. Feeds the TimeScrubber. This is a dedicated trip goal, not a maybe.
- **Locked-off clips.** 10–15s, no panning, same framing at different times. Feeds the VideoGrid.
- **One timelapse per trip.** 30–60 minutes propped somewhere stable.
- **Field audio.** 15–30s clips of moments that have a sound.
- **Simulator screenshots** posed via the debug scrubber for any app surface being discussed.
- **A depth-worthy wide shot** any time a scene has strong foreground/background separation.

## Not built yet, and deliberately

A few things the platform can do that this page doesn't demo, noted so they aren't forgotten.

- **View transitions** between the blog index and posts (the hero morphs into place). Site-level wiring, worth doing with the Astro upgrade.
- **An RSS feed.** The blog doesn't have one yet; passholders are exactly the audience that still uses RSS.
- **Reader polls** ("which park tonight?"). The site already has a serverless backend for the waitlist, so a one-tap poll with live results is possible without any account.
- **Live data blocks** (Astro 6+ live content collections). A post whose chart updates without a rebuild. Wants the framework upgrade first.
- **The calculator island**. The real payback calculator already embeds in guides, and can drop into any post where the math is the point.
